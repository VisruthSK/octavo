# Octavo 0.2.0

The release has three aims: exact transforms become the default and each is proven, the library takes a shape another renderer could embed, and the verifier becomes much faster without becoming less strict.

## 1. The product contract

One engine, four levels, named by goal:

| Level | Guarantee | Needs JavaScript |
|---|---|---|
| `exact` (default) | Every byte change is proven not to change what a browser renders | no |
| `serve` | Smallest file to send over a wire; adds pruning and other heuristics | no |
| `portable` | Smallest standalone file that works without JavaScript | no |
| `archive` | Smallest standalone file | yes |

Effort (`fast`, `balanced`, `maximum`) spends CPU on search and never changes what is permitted. Lossy images, font subsetting, remote fetching and packing are separate, explicit choices, never implied by a level or by effort.

Every edit carries one of four evidence classes, and the audit names the class:

- **Proven**: an oracle accepted the output as equivalent to the input, by construction.
- **Bounded-context**: justified by a complete declared resource set or a pinned generator version.
- **Heuristic**: inferred from word occurrences or conventions; can be wrong.
- **Intentional change**: lossy by design.

`exact` runs only Proven edits. The other levels may add the rest and say which ran.

## 2. Exact transforms

An exact transform returns a candidate. The engine adopts it only if an independent oracle accepts it; otherwise the original bytes stay and the report records the rejection. The oracle is a separate implementation from the transform, so one bug cannot satisfy its own check.

| Rule | Transform | Oracle compares |
|---|---|---|
| E1 | Canonical base64 for `data:` URLs | decoded bytes |
| E2 | Lossless PNG recompress | decoded RGBA, depth, colour type and the kept chunks |
| E3 | Guarded lossless WebP (8-bit, no profile, no partial alpha) | decoded RGBA, including colour under transparent pixels |
| E4 | Whole-font WOFF2 re-encode, no subsetting | every sfnt table |
| E5 | CSS comment removal | the token stream |
| E6 | CSS whitespace removal | the token stream |
| E7 | Digit-level number and colour shortening | parsed values |
| E8 | Zero-length unit stripping | parsed values |
| E9 | Empty-rule removal | the cascade input |
| E10 | Adjacent exact-duplicate collapse | the cascade input |

Gaps found in review, to close before exact becomes the default:

- **Custom properties.** Their values are substituted verbatim into unknown contexts. E5 comment removal, E7 and E8 must skip `--*` declarations, and E6 already does.
- **Math functions.** E8 must skip every math function (`calc`, `min`, `max`, `clamp`, the trigonometric and exponential functions), not only `calc`.
- **Observable stylesheet indices.** E9 and E10 delete rules, which shifts `document.styleSheets[i].cssRules[j]` for any script that indexes them. They run only on a document with no script that can observe the CSSOM; when a script is present they are skipped and reported as skipped.
- **Quotes.** Quote normalisation must not touch inline event-handler attributes or values that contain the other quote.
- **JavaScript.** Comment and whitespace removal (PR #110) is not exact: it changes `Function.prototype.toString` and stack text. It belongs to a lower level and is removed from `exact`.

Equivalence is stated at the Rust level and checked there: oracle unit tests, a property test per transform (output equals input under the oracle for generated inputs, idempotence where it holds), and fuzzing of the parsers. Transforms that the oracle proves are not sent through the browser verifier at all.

## 3. Library shape

The library takes bytes and options and returns bytes and a report. It needs no filesystem, network, environment, clock, process id, terminal or global thread pool; the CLI supplies those.

```rust
pub fn optimize(document: Document<'_>, options: &Options, host: &Host<'_>) -> Result<Outcome, Error>;
```

- `Options` groups settings by subsystem: level, effort, images, fonts, resources, packaging. Contradictory options are an error with a message, not resolved by priority.
- A transform is a type that implements `Transform` and declares its evidence class. A proven transform is built from an `Oracle`; there is no way to construct the proven class without one, so the type system, not review, enforces that `exact` only runs proven edits.
- `Outcome` lists what was applied, skipped and rejected, each with the rule, the evidence class and the committed byte delta. An entry appears only after the final candidate passed validation.
- Remote fetching is off by default and needs an explicit option and a resolver from the host.

## 4. Edit engine

The byte-range editing strategy stays, since it avoids reserialising untouched markup. The contract changes:

- Each edit names its asset and the input revision it was computed against.
- Conflicting edits are rejected with a reason, not silently dropped. Identical duplicates coalesce. Nested transforms on one extracted resource produce one enclosing edit.
- `Applied` is built after the final candidate is chosen. A regression test fixes the case where a report claimed an edit that was never committed.
- Reported deltas add up to the real output size, including loaders, data-URL overhead and notices.

## 5. Why exact can run by default

For any renderer the `exact` level is a post-render pass that is safe to run on every output: pure Rust and in-memory, deterministic (identical input and options give identical bytes, with a warm or cold cache), free of JavaScript and browser requirements, and honest about what it did. Heuristic levels stay opt-in, so a default pass cannot break a page. The library carries no renderer-specific names; Quarto 1 rules live in one optional profile that depends on detecting supported output.

## 6. Verifier

The verifier exists for the levels that are not proven. Measured on the pre-shrink 20,000-paragraph fixture and an A/A shard:

- Compare is about 1% of a shard (24.8 s against 2,283 s of capture).
- Page observation reads about 475 style properties per element; on 20,000 elements that is 9.5 million reads and 214 MB of strings. Caching per-property checks saves 4%; dropping logical-property aliases would save about 8%.
- Waiting is about half of captured time (initial settle 30%, interaction settle 12%, fonts ready 8%).

Plan, each step proven against the A/A run before it merges:

1. Concurrency across scenarios and documents (#106), with a test that fails if concurrency changes a verdict.
2. Condition-based settling where a condition replaces a fixed quiet window with the same guarantee, never a shorter window.
3. Exact edits leave the browser path, which removes their share of comparisons.
4. Costs become a short table of the heaviest documents per engine and a constant for the rest, replacing the 277-line `costs.json` and its log parser. A simulation shows this balances as well as the full table, because the slowest shard is set by one document either way.

Strictness rules: no retries, no relaxed tolerances (the one accepted tolerance is used sizes within 1e-4 px), and a self-comparison (A/A) run over the full corpus must show comparisons above zero in every shard and no differences before any verifier change ships.

## 8. Open questions

- Whether `portable` and `archive` should be separate levels or one level with a JavaScript option.
- How the oracle for fonts scales to variable fonts and to fonts with hinting programs.
- Whether the CLI default should detect Quarto 1 output and enable its profile, or require an explicit rule set.
