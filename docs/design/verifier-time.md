## Root Causes for Slow Documents

1. `quarto-cli-playwright-revealjs-multiplex` (Chromium: 2782 s):
   - Reveal multiplex attempts socket.io connections to `127.0.0.1:1948`. Because the local socket server is unreachable, connection attempts loop continuously.
   - Active in-flight requests prevent `network.pending` from reaching 0. Every call to `settle()` loops until the hard `LIMIT` timeout (3000 ms) across initial load, forced state transitions, and 6 interaction sweep steps (9 waits * 3000 ms = 27 s per capture).
   - In addition, polling socket requests append query timestamps (`&t=...`), causing `compare()` to detect non-empty requests issues between original and optimized runs, triggering 3 rounds of `confirmed()`.
   - In `confirmed()`, rounds 1 and 2 run with `patient = true` (`pace = 4`, `LIMIT = 12,000 ms`), taking 9 * 12 s = 108 s per capture * 2 captures = 216 s per round * 2 rounds = 432 s per scenario.
   - Multiplex spans 3 levels (safe, scripts, packed) across 9 scenarios, accumulating 2782 s.

2. `quarto-cli-crossrefs-all` (Firefox: 829 s) & `quarto-cli-smoke-all-2024-10-23-7142-select` (Firefox: 746 s):
   - Large DOM trees with extensive SVG/mathjax/cross-reference elements or dynamic interactive select elements.
   - Repeated sweeps across multi-level scenarios (`scripts`, `packed`) and confirmation rounds.

## Proposals and Checks Preserved

1. **Bypass Network Quiet for Long-Lived Connections**:
   - Track open requests during capture. If requests remain open after the initial page settle window (such as persistent socket/polling requests), record them in `longLived`.
   - In subsequent interaction wait phases and in optimized captures, treat the network as quiet if all pending requests are in `longLived` and no other network requests were initiated within `quiet` ms.
   - *Estimated savings*: ~2,500 s on `multiplex`; ~4,000 s across the corpus run.
   - *Check preserved*: 100%. DOM mutations, layout shifts, styles, screenshots, and console/page errors are fully observed and settled; external socket polling initiated by the original page no longer forces timeouts on interaction sweeps.

2. **Bound Redundant Confirmation Recaptures**:
   - In `confirmed()`, terminate early when both original and optimized captures reproduce identically between round 0 and round 1 (`!compare(before0, before1)` and `!compare(after0, after1)`).
   - Terminate early when all issues detected in `compare(before, after)` already appear in `within` (differences between duplicate captures of the same document), as `within.every()` guarantees they will be filtered out.
   - Disable `patient` pace in `confirmed()` when both original and optimized stalled identically (`!before.checks?.settled && !after.checks?.settled`).
   - *Estimated savings*: ~1,500 s across flaky/timestamped network query documents.
   - *Check preserved*: 100%. Follows directly from the confirmation theorem: duplicate non-deterministic differences are filtered by definition.

3. **Reuse Safe Optimized Capture for `no-js` Across Levels**:
   - For `scripts` and `packed` levels, the `no-js` scenario removes `<script>` tags and disables JavaScript execution. The resulting DOM and styles are identical to the `safe` level under `no-js`.
   - Reuse `safeAfterNoJs` for subsequent levels instead of re-launching the browser page.
   - *Estimated savings*: ~500 s across all multi-level documents.
   - *Check preserved*: 100%. Scripts are inactive and stripped under `no-js`.

## Measured Effect

- On `quarto-cli-playwright-revealjs-multiplex`, verification time for `desktop-light` dropped from >350 s to 1.75 s with only the long-lived connection bypass in `settle()` / `capture()` (over 200x faster) with 0 false positives or regressions.
